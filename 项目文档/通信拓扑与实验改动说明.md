# 通信拓扑与实验改动说明

更新日期：2026-10-11。此次改动以用户明确要求的通信拓扑和实际执行评估为依据。

## 1. 通信拓扑和路由

- `2.模型/tc_mdsm/data.py`：保留每个智能体到所属算力节点的一条接入边；删除生成算力节点互联的代码，改为生成所有无向智能体对。N 个智能体的链路数为 N + N(N-1)/2；N=100 时为5050条。
- `2.模型/tc_mdsm/types.py`：`Snapshot.path` 优先直连，没有直连时通过智能体做最少跳数搜索；支持智能体和算力节点端点，禁止算力节点中转。同一智能体内部传递仍为零链路。
- 接入边仍位于链路数组前N项，因此Rule-Latency使用接入时延的索引保持有效。
- E组编码、链路先验、候选路径重排、CP-SAT链路占用和World传输均沿用统一的`Snapshot.path`，不再经过算力节点间链路。
- 当前任务仍使用智能体所属的固定算力节点；没有另行引入动态算力节点选择或输入上传事件。算力接入链路作为物理拓扑的一部分存在，任务依赖数据在智能体之间传输。后续若要求每次计算都显式上传到算力节点，需要定义上传数据量和对应事件。

## 2. 截止时间对照

- `ModelConfig.deadline_policy` 与运行参数 `--deadline-policy` 有两个取值。
- `hard`：保留原来的预测结束时间不得超过截止时间的硬约束，默认值保持原语义。
- `evaluate`：允许在截止时间后排队执行；扩大有限规划时间域与归一化时延变量范围，保留技能/权限、容量、智能体互斥、DAG依赖、网络带宽约束。实际迟到仍计为失败。
- 两种模式都最大化接纳数，随后优化预测完成时间和风险；没有添加可靠性硬阈值、重试、备用分配算法或重规划。
- 用户希望先分配再看实际执行结果，因此本次主实验使用evaluate，并以同一权重和实例补做hard对照。两种模式的结果保存在不同目录。

## 3. 失败记录与缩减运行

- `2.模型/tc_mdsm/execution.py`：结果增加子任务数、依赖数、最少权限候选数、最少资源可行候选数、分配子任务数、实际成功子任务数、计划结束时间、截止时间和物理边数。统计来自实际样本及执行事件，不改写完成率。
- `2.模型/tc_mdsm/scheduler.py`：在FEASIBLE状态下未接纳的工作流标为`not_selected_within_budget`，避免将限时内未选中误称为已证明不可行。
- `3.实验评估/tc_mdsm_v3_runner.py`：新增`--scale-agents`和`--concurrency`以执行明确的缩减矩阵；`--method`也应用于评估；保存实际方法、拓扑、条件和模型配置；默认输出改为新的日期目录。
- `3.实验评估/tc_mdsm_v3_report.py`：绘制实验参数记录中实际运行的方法。
- `types.py`：修正missing注释，实际是对象×历史时间的整步缺失掩码。
- 用户已在data.py添加的四处解释性注释保留。本次没有修改基础能力JSON、原始负载CSV、任务模板、仿真失败概率或旧结果。

## 4. 求解起点和时长监督的修正

- 实测原全部拒绝提示在TC-MDSM的76条请求中产生4条`solver_no_incumbent`。增加`solver_start=serial/reject`及`--solver-start`，reject用于保留原起点对照，serial为默认值。
- serial先按预测时长和风险挑选候选，保守地串行安排各任务和传输，避开前批已保留方案，并把完整变量值作为CP-SAT提示。它不绕过CP-SAT，也不是超时后的备用执行策略；输出仍必须由CP-SAT返回FEASIBLE/OPTIMAL后提取。hard模式下不满足截止的串行请求不提示接纳，求解器仍可寻找并行方案。
- 多任务、依赖、同智能体传递及跨批资源占用的提示已用“固定全部提示变量后求解”检查可行性，验证脚本仅在命令行内存中执行。
- 同权重的串行起点对照中，所有方法都接纳73/76请求；剩余3条来自容量不足，未再出现无可行解记录。但按期完成数仍随分配和实际随机执行变化，不以接纳改善替代完成率改善。
- 所有学习方法旧权重的实际通信时长中位数约为预测的6.5—6.9倍；TC-MDSM通信原始残差约-5，接近exp(-2)的倍率下限。
- `2.模型/tc_mdsm/model.py`的时长损失从SmoothL1(log1p预测,log1p实测)改为SmoothL1(log预测,log实测)，以相对误差监督长计算和短传输。对每个方法相同，不调整实际标签或失败概率。零时长内部传递仍跳过，正时长取0.001秒下限。
- 为检查新损失是否改善通信低估，所有学习方法重新初始化并按相同种子、同一36条训练样本、两轮训练；新结果独立保存，不混入上述旧损失对照。
- 入口增加`--samples`，允许本次对照共用同一SQLite，不复制相同数据；实验参数记录样本来源、损失名称和求解起点。
- 短在线预算对照显示，0.5秒整批预算下，TC-MDSM仅分配10/52条请求；使用相同完整提示、关闭CP-SAT预处理后分配50/52条。求解阶段剩余预算不超过0.5秒且使用serial提示时，现关闭预处理，直接进入搜索；长预算仍使用原预处理。该规则对所有方法相同，不放松任何模型约束。0.1秒整批预算下仍受预测和建模时间限制，不能宣称达到100毫秒实时分配。
- `execution_policy=ready/planned`与`--execution-policy`区分实际就绪执行和原计划时刻下界。默认ready保留请求释放时间、智能体可用时间、资源容量、父任务和传输依赖，以计划开始时间作为待执行队列优先次序；资源与依赖满足时立即执行，不等待预测日历。不更换智能体、不重试、不重新求解。
- 在同一分配和同一规划耗时下，TC-MDSM由计划时刻模式的41/76按期完成、10条迟到，变为实际就绪模式48/76按期完成、1条迟到。完成总数由51变为49，原因是启动时刻改变也改变了工具健康、算力波动和实际随机执行结果；未隐藏这种差异。
- 全部六种方法均按相同ready规则重放同一批已保存方案，形成最终执行比较。保存的模型在planned验证方式下选择检查点，这一点在参数中明确记录；本次不为了执行方式再次挑选最有利权重。

## 6. 实验解释边界

本次是缩减诊断实验，不能代替默认12000训练样本、五种子、每条件30实例的完整比较。全互联使E组随N平方增长，旧145边的准备耗时和内存规模不能继续套用。所有图表以World实际执行结果为依据；模型预测值仅用于规划，不直接作为实测完成时间。

已经单独检查多跳路径、到算力端点的路径，以及不允许算力节点中转；验证代码通过命令行内存运行，未新增项目测试文件。
