# TC-MDSM 当前正式实验协议

## 当前口径

比较 TC-MDSM、GMATANN、HM-MATAS、Rule-Latency、Full-State、StaticGraph，共五个基线、六个方法。前两个外部论文基线是保留网络机制并接入统一监督头、CP-SAT 的适配，不是原始强化学习策略的完整复现。Full-State 与 TC-MDSM 使用相同的历史 GRU、DAG 任务查询、局部图预测、32候选预算、预测头与 CP-SAT 后端，仅取消状态组门控及维度掩码；因此不施加门控稀疏惩罚。两者共享候选预算和检索流程，具体候选可能因状态选择而不同。StaticGraph 使用最新状态异构图，不使用历史 GRU，也不使用任务条件稀疏门控；它与 Full-State 的主要区别是历史编码。图例中的 GMATANN 与 HM-MATAS 不加 adapted。

当前方法集合替换后，训练、冻结、评估、报告及方法测试均由 `METHODS` 自动使用 Full-State，输出目录名为 `full_state`。Full-State 必须重新训练，不重命名或复用旧方法的检查点、逐实例结果和冻结协议；历史记录保持原始身份。

完整技能及权限集合先参与检索，再取固定32个候选；无 F_v 预截断。状态维度预算保留配置键 `top_b`，语义为每组状态维度数，可通过 `state_dimension_budget` 读取，与候选数32不同。

CP-SAT 以接纳数优先，次级目标为归一化时间与负对数风险。0.90不再作为硬拒绝门槛。物理容量、权限、路径、依赖及计划截止时间仍由独立检查器验证。Rule-Latency 按观测时延筛选候选，并与其他方法共享 CP-SAT 调度后端。

首次节点或传输失败停止该请求的待执行事件；已经开始的事件排空后释放资源。执行没有重规划。完成率为首次按期成功数除以所有请求数；平均时延只计首次按期成功请求，包含初始决策、排队、计算和传输。失败及迟到请求在辅助惩罚指标中计两倍时限。

## 能力与仿真假设

能力数据已逐个保留，不再按源类型取并集。435个Skill保留原ID，分为视觉、规划、检测、文本四个能力族；常用能力随机重叠，专业能力稀疏重叠。工具与共享知识库权限同步配置。扩充的传感器和共享权限是仿真部署假设，不是真实智能体测量。

源能力文件和模型包在 `6.结果输出/2026-09-20_TC-MDSM旧协议/修改前备份`。能力生成配置包含原始文件SHA256和随机种子20260920。大规模环境循环使用这120个个体能力配置，动态状态及主机分配独立变化；不应声称1600个能力配置全部独立采集。

执行服务速率按0.5秒积分，受当前可用算力、历史趋势、个体速度和共享背景轨迹影响；传输按照动态有效带宽积分。链路竞争通过容量预留和排队实现，不模拟TCP或分组级拥塞控制。工具共享周期健康扰动，成功概率还受可靠性趋势和技能质量影响。源负载记录、合成参数、随机扰动应分别说明。

模型仅接收截止观测时刻的状态；未来扰动种子及执行标签不传给模型。验证环境审计同时报告候选差异、历史敏感性和外部噪声，不能据此声称门控或GRU已经带来收益。

## 正式运行

从项目根目录运行，Windows使用 `.venv-tc-gpu/Scripts/python.exe`，Linux使用安装相应依赖的Python：

```text
python 4.实验评估/tc_mdsm_v3_runner.py generate
python 4.实验评估/tc_mdsm_v3_runner.py train --device cuda
python 4.实验评估/tc_mdsm_v3_runner.py freeze
python 4.实验评估/tc_mdsm_v3_runner.py evaluate --device cuda
python 4.实验评估/tc_mdsm_v3_runner.py report
```

默认12000/1500/1500个工作流，隐藏128，最多100轮，五个种子7/17/29/43/61。五个学习方法共享训练和验证上限。前7轮不因验证停滞提前退出，其后耐心为10。逐轮校准使用验证集；检查点按验证完成率优先、惩罚时延次优选择。索引默认精确搜索，近似检索审计单列，未经召回和加速实测不宣称ANN优势。

数据以SQLite压缩逐样本读取，避免全部驻留内存。训练从 `last.pt` 恢复；评估跳过已经完成的实例。数据、代码或检查点身份不一致时拒绝混合结果，不删除旧文件绕过校验。

正式矩阵为3个复杂度、6个规模、7个并发条件，每种子每条件30个实例。规模每10智能体1计算节点；并发固定100智能体/10节点。场景只作来源元数据，不分图。全部14400个实例文件完成后才生成正式四图。

输出目录 `6.结果输出/2026-09-27_TC-MDSM正式实验/运行`。旧协议目录内的 `最终贯通` 等子目录是小样本流水线验证，不可替代当前正式实验。

## 结果与资源说明

输出包括四幅PNG/PDF、逐请求CSV、逐批决策时间、种子置信区间、共同成功请求时延和Holm校正的配对比较。决策耗时按批记录，包括模型预测和计划检查；零成功请求不填零时延。

GPU实测来自RTX5060Ti 8GB、PyTorch2.7.1+cu128：128维中等任务训练约0.191秒/步，1600智能体困难任务推理峰值约2.30GiB。12,000步单轮约38分钟，仅为短跑外推，不包含数据读取、概率校准与CP-SAT验证。25次学习模型训练各100轮需要较长时间；早停会缩短，完整验证与评估会增加。不能承诺在一次交互内获得正式结果。

当前协议的验收测试使用 `自动化测试/test_tc_mdsm_v3.py`。

当前四项图中实验一、二为柱状图，实验三、四为双指标曲线图。2026-09-20 的旧协议结果包含 Full-State 且未完成，不可混入当前正式实验。
