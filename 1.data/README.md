# 数据部分

本目录集中管理原始数据、基础仿真表、事件序列训练集以及所有数据转换脚本。模型结构代码位于 `../2.模型/`。

## 目录与数据集

| 路径 | 作用 |
| --- | --- |
| `1.负载数据/` | 12 个虚拟算力节点清单和 17,292 行节点负载时序 |
| `2.链路数据/` | 120 个智能体的全连接逻辑拓扑、固定一对一算力接入及 48 个动态观测时间点 |
| `3.智能体能力数据(包括智能体环境和知识库、API权限)/` | 120 个派生智能体的能力、API、知识库、上下文和传感器状态 |
| `4.智能体可靠性/` | 调用次数、成功率、平均耗时和工具调用失败率 |
| `5.任务数据/` | 72 个复杂任务及 351 个子任务；显式保存难度、执行步骤和 DAG 前置关系 |
| `6.事件数据/` | 事件类型、关系类型编码表及示例事件流 |
| `实验室的智能体能力列表/` | 两部分原始智能体能力卡；本轮生成只读取 part1 |
| `数据集处理与生成/` | 基础表生成、Alibaba 处理及训练窗口转换脚本 |
| `ma_tgn_data/` | `TrainingCase` 序列化、基础表窗口转换和 MA-TGN 状态仿真器 |
| `datasets/sixg_ma_state/` | 由编号基础表生成、供训练器直接读取的 train/val/test JSONL |
| `raw/` | Alibaba GenAI cluster trace 原始文件和旧容器级合并结果 |

## 一键重建

在项目根目录运行：

```powershell
python "1.data/数据集处理与生成/generate_simulation_datasets.py"
```

该命令使用固定种子生成所有编号关联表，写入 `dataset_manifest.json`，执行编号、外键和知识库占比检查，并自动将新基础表转换为训练器所需的滑动窗口 JSONL。默认取 16 个源时间戳组成一个窗口，生成 72 个互不重叠的窗口，并按时间顺序划分为 54/9/9 个训练、验证和测试样本。改变虚拟算力节点数量时使用：

```powershell
python "1.data/数据集处理与生成/generate_simulation_datasets.py" --compute-nodes 16 --seed 20260814
```

如果只修改了基础表，可不重新处理原始数据，直接重建训练窗口：

```powershell
python "1.data/数据集处理与生成/build_training_jsonl_from_foundation.py"
```

## 关键字段解释

- 智能体表第 6 列为 `运行环境`，用于补齐用户列说明中缺失的第 6 列。
- 智能体知识库接入比例固定控制在 20% 以下；当前默认约为 14.2%。
- 智能体之间默认两两可达；无向边只保存一次。每个智能体固定且仅连接一个算力节点。
- 链路状态含 48 个覆盖完整负载时间范围的观测点。每条链路的标称带宽固定为 500/1000/2000/3000 Mbps 之一；时延、丢包率和抖动随拥塞平滑变化。
- 算力节点是从容器 IP 稳定哈希得到的虚拟服务器。CPU 负载不可由当前源数据恢复，故只提供明确命名的 `服务器负载率代理`。
- `agent_capabilities.json` 和 `tasks.json` 保留 CSV 中没有展开的场景、源类型和完整 skill 溯源字段。
- 算力节点输入只编码 `GPU算力剩余量`、`内存剩余量` 和 `显存剩余量`；其他源字段仅用于溯源。
- 任务节点只编码 Skill id、端到端时延和准确率。输出要求与字段完整率保留在基础表中，但不进入当前模型。
- CSV 中每个复杂任务行后紧跟其子任务行；相同 `执行步骤` 的子任务可并行，`前置子任务id` 与 `DAG边列表` 可直接审计依赖。
- 训练窗口保证候选集合中存在满足必需 Skill 的智能体，监督标签对应的智能体也必须具有该 Skill。

## 事件编码

事件编码固定为 0—5：上下文更新、环境更新、算力更新、链路更新、任务结果和能力更新。系统图关系只含算力访问和通信；子任务依赖仅存在于任务 DAG query 中。代码枚举位于 `../2.模型/ma_tgn/types.py`，数据字典位于 `6.事件数据/`。

事件不是“模型训练完才使用的第二套数据”。训练时，事件按时间顺序组成节点和边的历史输入，GRU 学会如何更新隐藏状态；部署后，新事件继续使用已经训练好的 GRU 参数在线更新隐藏状态，通常不需要每来一条事件就重新训练模型。基础 CSV 是完整状态事实表，JSONL 中的事件则是按训练窗口整理后的状态更新序列。
