# 论文实验运行

当前实现尚未完整对齐论文，尤其缺少可靠性硬约束、失败重试与32→64候选扩展。以下为实际代码设置，不代表论文已完成复现。

## 一键运行

双击本目录中的 `运行实验.cmd`。它使用项目根目录的 `.venv-tc/Scripts/python.exe` 运行本项目的 `tc_mdsm_paper_runner.py`，依次生成数据、训练六种方法、进行动态仿真并输出四幅图。每次新运行自动创建 `4.结果输出/日期_时分秒_论文实验`，不覆盖历史实验。

也可在项目根目录的 PowerShell 中执行：

```powershell
python -B -u '3.实验评估/tc_mdsm_paper_runner.py'
```

仅查看设置，不开始实验：在上面的命令末尾加 `--describe`。换用其他已安装项目依赖的环境时，可将环境变量 `TC_MDSM_PYTHON` 设为该环境的 Python 可执行文件绝对路径。

## 默认条件

- 训练/验证/测试数据库实例：12000/1500/1500；测试条件另从test划分生成。
- 种子：7、17、29、43、61；最大100轮；每种子每条件30批。
- 六方法：TC-MDSM、GMATANN、HM-MATAS、Rule-Latency、Full-State、StaticGraph。
- 复杂度：简单、中等、困难；100智能体、10计算节点、单工作流。
- 并发工作流：1、2、4、8、16、32、64；100智能体、10计算节点、中等难度。
- 智能体规模：50、100、200、400、800、1600；计算节点按5、10、20、40、80、160扩容；单工作流、中等难度。
- 8候选，每次最多4工作流分批规划；所有方法统一30秒整批在线规划预算。
- hard预测截止约束、serial初始求解提示、ready实际就绪执行；无重试。
- 训练优先使用CUDA；所有条件和方法统一在CPU上评估，2个PyTorch线程。需要GPU评估时显式加 `--evaluation-device cuda`，不要混用不同设备的限时规划结果。

完整矩阵有16个条件、14400个批次文件、122400条请求。完整训练和大规模全互联状态处理耗时较长；没有预设方法排名或目标数值。脚本只记录World动态仿真输出，拒绝、执行失败、传输失败和迟到均纳入完成率分母。

为了降低大规模推理内存，`2.模型/tc_mdsm/model.py`按每块512个对象编码状态，训练路径保留原实现。只有GMATANN在推理时保留后续计算使用的A/C/R历史编码；其他方法保留当前状态编码。该修改未改变状态特征、权重、候选数或约束。

## 输出和续跑

`实验参数.json`保存实际配置；`数据/samples.sqlite`保存数据；`训练/`保存权重；`逐实例结果/`保存请求、方案和执行事件；`实验结果图/`保存四幅英文PNG/PDF、逐请求CSV及统计表。前两幅为柱状图，后两幅为双栏折线图，每幅图有独立图例，无阴影和误差条。统计CSV保留95% t区间和有效时延种子数。

均值按种子计算。成功时延仅对首次按期成功工作流统计，零成功条件保持缺失；全请求惩罚时延将失败和迟到记为两倍请求时限。全局准备耗时单独记录，在线预测、约束构建与CP-SAT求解均属于在线决策耗时。

续跑时使用同样的运行参数，在命令末尾追加：

```powershell
--output '4.结果输出/这里填写原运行目录名称' --resume
```

已保存评估批次会跳过。不同配置应使用新目录；脚本会拒绝将不同设置混入已有目录。只重新绘图时运行：

```powershell
python -B '3.实验评估/tc_mdsm_paper_runner.py' report --output '4.结果输出/这里填写实验目录名称'
```

绘图复用`tc_mdsm_v3_report.py`的统计逻辑，仅使用`paper_style=True`切换英文无误差条版式。现有runner默认图表设置保留。

## 本次验证

六种方法在5050条链路、包含缺失状态的快照上，分块编码与原编码的当前状态向量通过数值一致性检查；GMATANN使用的历史序列也一致。另以3/3/3样本、一个种子、1轮、每条件1批的小规模临时运行验证了六方法的生成、训练、评估、四图输出和续跑，临时验证产物已自动清理。完整五种子与1600智能体矩阵尚未执行，这些检查不代表性能比较结论。
